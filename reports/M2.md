## 1. What we built

### Monitoring Brief

- `services/collectors/brief.py` loads each `config/monitoring-brief/v*.yaml` into `monitoring_brief_version`. The load is idempotent by content hash. The hash does not include the version number.
- `config/monitoring-brief/schema.yaml` is the JSON schema of a brief. The loader also checks unique ids, known licence codes, valid schedules and known organisation ids.
- If no version is active, the loader activates the highest version. Each activation writes a `brief_activation` row and a `BriefVersionActivated` event in stream (`brief`, `main`).
- `derive_version()` makes a new version from an old version with changes. `create_version_from_yaml()` makes a new version from YAML text. `diff()` gives the changes between two versions. It matches list entries by id.
- `brief_sources()` gives each source that the collectors fetch: the Google News queries, `sources.news` and `sources.early_signal`. Proposed sources are not collected.

### Governance start-up step

- `services/governance/bootstrap.py` registers the YAML text of the active brief as a source document (type manual, publisher "Strata Monitoring Brief v1", licence full).
- It makes one entity registry row and one `EntityIdentified` event for each watched site (57) and each organisation (71). The evidence quote is the span of the YAML text that names the site or the organisation. Each evidence row is verified against the text.
- Geometry comes only from the brief geometry, with `geometry_source` {dataset, dataset_url, licence, approximate}. A null geometry stays null (36 sites).
- It writes one `RelationshipAsserted` event for each operator link (`operates`) and each owner link (`owns`), with an evidence span.
- It loads the two entries of `sources.proposed` as `SourceProposed` proposals (policy admin_review) with a `ProposalCreated` event in stream (`proposal`, id).
- `services/governance/source_proposals.py` creates and approves source proposals. An approval makes a new brief version with the source, activates it and writes `ProposalApproved`. A user cannot approve an own proposal.

### Collectors

| Module | Content |
|---|---|
| `services/collectors/http.py` | The one HTTP client: User-Agent "Strata/0.1 (+contact: STRATA_CONTACT_EMAIL)", robots.txt check with a cache, a rate limit for each domain (injectable clock), the google_news_only guard, redirects with a check at each hop, three retries with backoff, conditional GET |
| `services/collectors/feeds.py` | RSS and Atom (feedparser). Google News search feeds with the brief edition (hl, gl, ceid). Title and description only. The item keeps the publisher link |
| `services/collectors/web.py` | Pages (trafilatura main text), sitemaps (each listed page through the same client) and PDF responses |
| `services/collectors/pdf.py` | pdfplumber text, `page_map` with the start offset of each page, OCR for pages with no text layer (Tesseract if the binary exists, else RapidOCR). The engine goes into `source.metadata` |
| `services/collectors/manual.py` | File or URL upload by an analyst |
| `services/collectors/snapshot.py` | Loads `data/snapshots/*/items.jsonl` once as sources of type snapshot, link_only, read_at_source true |
| `services/collectors/pipeline.py` | Steps 2 to 10 of the pipeline: object storage, NFC text, content_hash, simhash, exact and near duplicates, language, source row, excerpt, enrichment job |
| `services/collectors/runner.py` | One run for each source. A `collector_run` row for each run. A `dead_letter` row after the retries. One failure does not stop the other sources |
| `services/collectors/schedule.py` | Due calculation in Africa/Lusaka, with jitter |
| `services/collectors/retention.py` | `purge_expired_text()` for verify_then_purge sources |
| `services/common/storage.py` | S3 backend (boto3) when `STRATA_S3_ENDPOINT_URL` is set, else a filesystem backend under `STRATA_STORAGE_DIR` |

### Queue and worker

- `services/queue.py` has the Procrastinate App and the tasks `collect_source`, `purge_expired_text` and `dispatch_due_sources`. `services/enrichment/tasks.py` has the `enrich_source` stub for M3.
- `services/worker.py` runs the worker. The periodic dispatcher runs each minute. The purge runs each hour.
- Code outside the worker defers jobs through a synchronous connector. A queueing lock stops a second waiting job for the same source.

### API (`services/api/routers/sources.py`)

`GET /api/sources/health`, `GET /api/sources/known-gaps`, `GET /api/sources/{id}`, `POST /api/sources/manual`, `GET /api/briefs`, `GET /api/briefs/diff?from=&to=`, `GET /api/briefs/{version}`, `POST /api/briefs`, `POST /api/briefs/{version}/activate`, `POST /api/proposals/{id}/approve-source`. A viewer gets 403 on each write. The API gives the text of a source only when the retention policy is full. The typed client in `packages/api-client` is regenerated.

### Fixtures

- `tests/fixtures/server.py`: `python -m tests.fixtures.server --port 8765`, and `start_server()` for tests. It serves three RSS or Atom feeds and one extra feed for the proposed source, Google News search feeds at `/rss/search?q=`, two web pages, a sitemap, robots.txt that disallows `/private/`, and two PDF files. It supports ETag and If-Modified-Since, logs every request and can fail a path on demand.
- `tests/fixtures/make_pdfs.py` makes the two PDF files. One file has no text layer.
- `tests/fixtures/brief-fixture.yaml` is a small brief whose sources point at the fixture server.
- `scripts/load_fixtures.py` (`make fixtures`) activates the fixture brief, runs all collectors once, then activates the previous brief again. A local smoke run collected 16 fixture sources and restored brief v1.
- All fixture articles are synthetic test data about the watched sites.

### Other changes

- Migration `db/migrations/0100_collectors.sql`: unique brief key for each entity type, three new columns in `collector_run`, and indexes.
- `config/collectors.yaml`: schedules, jitter, HTTP rules, retry, near duplicate threshold, OCR settings, the map of the nine early signal types, and the snapshot settings.
- `services/common/settings.py`: `STRATA_GOOGLE_NEWS_BASE_URL` and `STRATA_FIXTURE_BASE_URL`.
- `pyproject.toml` and `uv.lock`: the OCR fallback uses opencv-python-headless. The GUI build of OpenCV needs X11 libraries that the slim image does not have.
- `tests/python/conftest.py`: one import line for the collector fixtures.
- `scripts/compute_lifecycle_intervals.py`: `zip(..., strict=False)`. Without this change, `ruff check` fails in CI (B905).
- `.gitignore`: `.data/` (local object storage).

## 3. New assumptions

| No. | Subject | Default that Claude Code uses |
|---|---|---|
| 22 | Time of the daily and weekly runs | Daily at 05:00 and weekly on Monday at 05:00, Africa/Lusaka (config/collectors.yaml) |
| 23 | Near duplicate threshold | Hamming distance 3 or less of a 64 bit simhash over shingles of three words. Only sources fetched in the last 60 days are candidates |
| 24 | robots.txt that does not load | HTTP 404 allows all paths. HTTP 401, 403, 5xx or a network error disallows all paths. The cache keeps a result for 24 hours, or 10 minutes after an error |
| 25 | Retry rule | Three retries after 2, 4 and 8 seconds, for network errors and HTTP 429, 500, 502, 503 and 504. Other 4xx responses are not retried |
| 26 | Sitemap limit | 50 pages in one run. A sitemap inside a sitemap is not followed |
| 27 | Web page sources | One document for each configured page. The collector does not follow the article links of a section page |
| 28 | Licence of a manual upload | verify_then_purge unless the analyst gives a licence code from the brief. A manual URL obeys robots.txt and the google_news_only guard |
| 29 | Object storage keys | sources/<source id>/raw.<ext> and sources/<source id>/text.txt. A link_only source keeps no raw file |
| 30 | Excerpt | The first 280 characters of the text after whitespace is collapsed. The purge keeps the excerpt |
| 31 | Google News item URL | The publisher URL when the Google News link carries it. Else the Google News link. The metadata keeps the Google News link and the publisher site |
| 32 | Section of an approved source | sources.early_signal when the proposal gives a source_type, else sources.news |
| 33 | Version number of a new brief from the API | The next free number. The content hash does not include the version number, so the same content gives the existing version |
| 34 | OCR | A page with fewer than 20 characters goes to OCR at 200 dpi. Tesseract when the binary exists, else RapidOCR |
| 35 | Language | langdetect with a fixed seed. No language for a text with fewer than three words |
| 36 | Watch level of a site that leaves the brief | The start-up step sets watch none for a site that the active brief does not list |
| 37 | Health window | Error rate and documents for each run from the last 20 runs of a source |
| 38 | Snapshot enrichment | Each new snapshot source gets an enrich_source job, like any other source |

## 5. Known risks for M3

1. RapidOCR drops many spaces between words ("ENERGYREGULATIONBOARD"). CI installs Tesseract, so CI uses Tesseract. The local Docker image has no Tesseract because the apt mirror is blocked here. Evidence checks on OCR text can fail with RapidOCR. Install Tesseract in the image on a normal network.
2. The near duplicate threshold of 3 is strict for short articles. A test with an article of about 100 words and two small edits gave a distance of 6. The fixture article of about 350 words gives 3 or less. Tune the threshold with real data.
3. Most web sources in brief v1 are section pages. The web collector stores the main text of the section page, not the linked articles. M3 needs feeds, sitemaps or link discovery for these sources.
4. The robots.txt of news.google.com may disallow the RSS search path for a generic agent. Then the live Google News collection fails on its first run. The build could not check this.
5. `enrich_source` is a stub. The start-up step already puts 146 snapshot jobs on the queue. M3 must process them, and must accept the stub jobs that already ran.
6. If the queue is not reachable, a new source has no enrichment job. The pipeline logs the error. M3 can add a sweep for sources without enrichment.
7. The rate limiter is for one process. Two worker processes do not share it.
8. Tests do not cover the S3 backend. The compose stack uses it through SeaweedFS.
9. At the first worker start, every source is due. All collect jobs start in the first minute, with jitter.
10. Merge risk: `packages/api-client` (generated), `pyproject.toml`, `uv.lock` and `tests/python/conftest.py` can conflict with Track 2. Run `pnpm api-client` again after the merge.
11. Tests on the shared PostgreSQL server set the password of the role strata_app. Two sessions that run tests at the same time can break the connections of each other.
