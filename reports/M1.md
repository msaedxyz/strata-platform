# M1 progress report: repository, Compose, CI, schema, event store, OIDC

## 1. What we built

- The repository layout from docs/02: apps, packages, services, config, prompts, db/migrations, tests and docs.
- Docker Compose with PostgreSQL (PostGIS, pgvector, pg_trgm), Keycloak, SeaweedFS S3, Mailpit, the migrate job, the API, the worker and the web frontend.
- The migration runner. It makes the roles strata_owner and strata_app and applies the grants.
- The event store. A trigger rejects UPDATE, DELETE and TRUNCATE for every role. CHECK constraints make fact events need evidence and engagement events need a human actor. The insert trigger calculates the sequence and the hash chain, and rejects evidence that does not exist or is not verified.
- The governance event writer. It checks each payload against config/event-schemas.yaml.
- The projector with pure folds, rebuild and projection hashes.
- The API with OIDC bearer checks from the Keycloak JWKS, roles, the security log and the live stream (SSE from PostgreSQL NOTIFY).
- CI: Python lint and tests, frontend lint, typecheck, tests and build, the OpenAPI client check and a gitleaks scan.
- `make setup` makes .env with random secrets. No secret is in a file in the repository.
