# M5 progress report: design system, panel framework and shell (Track 2)

Date: 2026-09-26. Branch: worktree-agent-a8be7317caf5b831e (based on build/strata at e8043e0).

## 1. What we built

1. packages/eslint-plugin-strata: the ESLint rule `strata/no-raw-values`, a shared ESLint configuration and a stylelint configuration. They stop raw colour and size values (docs/07 rule 6).
2. packages/design-system (@strata/design-system):
   - Tokens in DTCG format: tokens/infora.tokens.json (base tokens, provisional) and tokens/strata.component.tokens.json (structural sizes, provisional).
   - scripts/build-tokens.mjs makes src/tokens.css and src/tokens.ts. scripts/sync-tokens.mjs (`pnpm tokens:sync`) takes audit/tokens.json after the audit.
   - 33 components with 168 Storybook stories (Storybook 10). The components use only token variables.
   - The visual parity harness (visual/). It reads audit/components.md and audit/components/<component>/<state>.png. It skips when the audit does not exist.
3. packages/panel-framework (@strata/panel-framework): react-grid-layout grid, panel registry, panel picker, drag, resize, snap, collapse, maximise, close, add, workspaces with default layouts, layout storage behind the `LayoutStore` interface (localStorage, versioned keys per user), reset layout. BEHAVIOUR.md records the provisional behaviour.
4. apps/web (@strata/web): the Vite app. OIDC login with Keycloak (PKCE, callback route, silent renew, logout through POST /api/session/logout and end-session), POST /api/session/login after login, top bar with search and command input, navigation rail, ticker strip slot, the four default workspaces, 18 placeholder modules in a module registry, keyboard shortcuts from one configuration file, live connection (`useLive`) with reconnect, role-aware controls, a test-only auth driver for E2E.
5. CI: a new job `frontend-e2e` runs the Playwright end to end tests and the visual test.
6. docs/frontend-components.md.

Screenshots of the Strata shell are in reports/notes/m5-screenshots/ (1920x1080 and 1440x900 for each workspace, and the command input and shortcut help). No Infora screenshot exists to put next to them (docs/07 criterion 10 is blocked).

## 7. Known risks for the next milestone

1. Every visual value and behaviour is provisional. The audit can change tokens, sizes, components and interactions. The token pipeline and the harness make the change mechanical, but the E2E tests for panels and shortcuts can need changes.
2. criterion 2 and criterion 1 (with the audit) stay blocked until someone runs the audit from a network that can reach beta.infora.io.
3. The design system ships as TypeScript source. The web build compiles it. A second flavour (Infora) must use the same bundler setup, or the package needs a library build.
4. Performance criteria 6 and 7 (10 000 signals, 500 deals) need list virtualisation in DataTable and FeedItem lists in M6. The DataTable renders every row now.
5. The pnpm-workspace.yaml change (onlyBuiltDependencies: esbuild) and the root package.json scripts can conflict with other tracks at merge.
