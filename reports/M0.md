# M0 notes: Infora audit tooling

Date: 2026-09-26
Milestone: M0, audit of Infora (docs/01-audit.md)
Status: The tooling is complete and tested. The live audit is blocked. M0 is not complete.

## 1. Summary

The build environment cannot reach Infora. The network policy blocks beta.infora.io. INFORA_REPO_PATH is not set, so the Infora source is not available.
Thus the audit did not run against Infora.

This work gives a complete audit tool in tools/audit. The tool runs the full audit with one command when access exists.
A local mock site proves each part of the tool. The mock site has a login form, a navigation, panels in a grid, a ticker, a table, a modal, a form with a Save button that sends a POST request, and pages that the audit must skip.

## 2. The block

| Item | Observation |
|---|---|
| beta.infora.io | The egress policy denies the connection on 2026-09-26. `curl https://beta.infora.io/dashboard` gives "CONNECT tunnel failed, response 403" from the proxy. |
| INFORA_REPO_PATH | Not set. The Infora source is not available. docs/01-audit.md, "Source code first", cannot start. |
| INFORA_URL, INFORA_USERNAME, INFORA_PASSWORD | Not read and not needed for the tooling. The tool reads them from the environment only. |

To remove the block, do one of these:

1. Allow outbound HTTPS to beta.infora.io in the environment network policy, and set the three INFORA_* variables as secrets.
2. Run the audit on a computer that can reach Infora. Use the steps in tools/audit/README.md.
3. Set INFORA_REPO_PATH to a clone of the Infora source. Then the design system can come from the source (docs/02-architecture.md, principle 2).

## 8. Proposed rows for docs/assumptions.md

| Subject | Default that Claude Code uses |
|---|---|
| Audit output directory | `<repository>/audit`, ignored by git. AUDIT_OUT_DIR can change it |
| Sensitive pages | A URL or page text that suggests credentials, API keys, billing, users, team, profile, account or admin. A password field. Three or more e-mail addresses on the page |
| Personal data in screenshots | Masks on password and e-mail fields, on the user name and on text that looks like an e-mail address |
| Value-change observation | 30 seconds on the first view |
| Grid row height | When more than one row height fits the geometry, the guess is the smallest candidate of 20px or more. layout-system.md lists all candidates |
| Neutral state colour | color.state.neutral uses the secondary text colour. This is a guess until the audit shows a neutral state |

## 9. Known risks for the live audit and for M1

1. If Infora reads data with POST requests (for example GraphQL queries), the guard blocks them and some panels stay empty. network.md shows each blocked request. A change needs Mohamed's approval.
2. A login with single sign-on on another site, a CAPTCHA or a second factor needs a person. The tool stops with exit code 2.
3. Heuristics find components by class names and ARIA roles. Components drawn on a canvas can be missing. A review of components.md against the screenshots is necessary.
4. Live data can show a colour or a size that appears only for a short time. The second sample and the check can then differ. A repeat of check-tokens shows if the value is stable.
5. The grid estimate can fit more than one row height. The values in the bundles or the Infora source must confirm it.
6. M5 depends on the live audit. Without it, packages/design-system has no tokens or components to build from.
